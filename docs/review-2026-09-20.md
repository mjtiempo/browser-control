## High — security

### 1. `label()` put a password's value in every element description

- **Found at:** `dom.py:194-203`; surfaced in replies at `dom.py:2262` and
  `dom.py:2331`.
- **Trigger:** `tab focus "Password Field"` then `tab insert <secret>` — the
  shared `PRELUDE`'s `label(el)` included `el.value`, so `describe(el)` (and
  `_text_reply`'s `active` field) echoed the secret back in the JSON reply,
  even though `insert` marked it for log redaction and its docstring promised
  the text "is NEVER echoed".
- **Verified:** full read of every `label`/`describe` consumer; the live
  battery's own password check asserted only the log, never the reply.
- **Fix:** `(el.type === 'password' ? '' : el.value)` in `label()` (other
  values stay, because `find` matches an input by them). The live battery now
  asserts `secret not in json.dumps(inserted)`; it failed before the fix and
  passes after.

### 2. Redaction ran after argv truncation — a >4 KB secret was logged in cleartext

- **Found at:** `audit.py:129-131,142` (`_censor(_brief(...))`).
- **Trigger:** mark a 5000-char secret, then write the log. `_brief` truncated
  it to 4096 chars + marker, which no longer *contains* the full secret, so
  `_censor` passed it through: the first 4096 characters hit disk still marked
  `"redacted": true`.
- **Verified:** runtime PoC — `"S" * 5000` appeared in the log line.
- **Fix:** `_brief(self._censor(...))` (redact, then cap) plus a short-write
  loop in `_append`. Regression test
  `t_audit_redaction_beats_truncation` fails on the old order.

### 3. `profile seed` wrote through a symlinked target into a live profile

- **Found at:** `profile.py:305-352`; `reset` guarded against a top-level
  symlink, `seed` did not, and liveness compared lexical spellings.
- **Trigger:** `<root>/link -> <root>/real`, a browser running on `real`, then
  `profile seed --profile <root>/link` — `_is_managed` accepted it (realpath
  is under the root), `_live_pid` saw no browser, and every file was copied
  through the link into the live profile.
- **Verified:** runtime PoC — `seed` returned `ok: true` and wrote
  `real/Cookies`.
- **Fix:** `_target` refuses any symlinked profile, for the default instance
  too. Regression test `t_profile_symlink_target_is_refused`.

### 4. The HTTP CDP read followed `http_proxy` off loopback

- **Found at:** `cdp.py:86` (`build_opener(_LoopbackOnly)`).
- **Trigger:** `http_proxy=http://10.0.0.9:3128` in the environment — urllib's
  default `ProxyHandler` stayed installed, so the request whose answer is
  parsed as CDP JSON went to the proxy, which could answer for a dead port and
  supply a forged `webSocketDebuggerUrl`.
- **Verified:** runtime PoC — a fake proxy received
  `GET http://127.0.0.1:<dead>/json` and its forged body was returned.
- **Fix:** `build_opener(_LoopbackOnly, ProxyHandler({}))`. Regression test
  `t_http_read_never_uses_a_proxy`.

## Medium

### 5. `open` proved its browser with the stale endpoint it had just ignored

- **Found at:** `browser.py:1330-1341,1352`, `_wait_port` at `1022-1029`.
- **Trigger:** a stale `DevToolsActivePort` whose port is held by another
  answering endpoint: `launch` spawns a browser, then `_wait_port` returns on
  the first poll because *something* answers there, and the reply reports the
  stranger's port and tabs as `started: true`.
- **Fix:** `_wait_own_port` re-judges the owner of the **current** port file
  (memo evicted) until it verifies. Regression test
  `t_wait_own_port_requires_a_verified_owner`.

### 6. `tab close` could end in `cdp-not-local` after the tabs were gone

- **Found at:** `browser.py:1623` — `_tab_count()` used `_drivable()`'s strict
  form, so closing a browser's last tab (which exits the browser) turned the
  read-back into a refusal about an unrelated answering browser.
- **Fix:** `_drivable(strict=False)` for the count; regression test
  `t_tab_count_does_not_refuse_on_a_stranger`.

### 7. `/proc/<pid>/cmdline` was flattened and parsed as if it were argv

- **Found at:** `browser.py:270-300`, `337-340`, `457-458`.
- **Trigger:** a profile path containing a space (`--profile "$ROOT/work
  profile"`, or a root with a space): `_cmdline_value` split on whitespace, so
  the CLI lost its own browser, reported a truncated `profile`, and `close`
  said "no managed browser was running" while one was.
- **Fix:** NUL boundaries preserved (`browser._proc_text`, `cdp._proc_text`)
  and `_cmdline_value` splits on NUL when present, whitespace otherwise. A
  main process whose URL merely *contains* `--type=` still stays a main
  process; Chrome's rewritten child cmdlines (spaces, one trailing NUL) are
  still excluded. Regression test `t_cmdline_value`; the live battery (which
  exercises real Chrome cmdlines) passes.

### 8. A browser on its vendor default profile can never verify — message corrected

- **Found at:** `browser.py:457-458`, `821-826`.
- **Issue:** `endpoint_owner` requires the listener's own cmdline to carry
  `--user-data-dir=<profile>`. A browser on its default profile has no such
  flag, so `attach --port N` / `close --pid N` refuse with advice
  ("the port file is stale or the port was taken") that is simply untrue.
- **Decision:** the verification rule is deliberately narrow and was **not**
  weakened. The refusal now names the real cause, and README states the
  requirement (start the foreign browser with an explicit
  `--user-data-dir`). Whether to accept an exe + `--remote-debugging-port`
  identity for default-profile browsers is left as an explicit design call.

### 9. `profile info --profile <path>` walked any caller-named tree, unbounded

- **Found at:** `cli/main.py:1131` → `profile.py:267-271`, `_tree` at `66-110`.
- **Trigger:** `profile info --profile /` descended the entire filesystem with
  no depth/entry/time bound, outside the root the verb is documented for, and
  `--deny file` could not stop it.
- **Fix:** `info` refuses a scoped path that is not managed (`not-managed`,
  the refusal `docs/plan.md` already documented). Covered by
  `t_profile_symlink_target_is_refused`.

### 10. A closed stdout reader produced status 120, not `ERR[broken-pipe]`

- **Found at:** `cli/main.py:1178,1185-1192`.
- **Trigger:** a 2–3 KB reply stays in stdio's buffer, so `print` raises
  nothing; the failure surfaced at interpreter shutdown as `Exception
  ignored` and exit 120, overriding the promised refusal/2.
- **Verified:** runtime PoC — old binary exited 120 with `Exception ignored`.
- **Fix:** flush inside the `try`, and point stdout at `/dev/null` in the
  handler so the shutdown flush cannot fail again. Regression test
  `t_cli_broken_pipe_is_a_refusal` (exit 2, `ERR[broken-pipe]`, no
  `Exception ignored`).

### 11. The live battery hard-coded Chrome

- **Found at:** `live_test.py:1264`, `:1283-1284`, `:549`.
- **Issue:** `prereq()` accepts every Chromium family, but the battery read
  `ROOT/google-chrome-stable/DevToolsActivePort` and asserted `"Chrome"`, so
  the only live proof of the `cdp-not-local` guard could not run on a
  chromium-only machine.
- **Fix:** the real profile path from `STATE`, and family-token checks; the
  managed-profile keying is already pinned hermetically.

## Left open (reported, not changed)

1. **Default-profile attach** (finding 8): accepting an exe +
   `--remote-debugging-port` identity is a deliberate design call, not made
   silently.
2. **`tab wait --for js` is classified `code` only**, so `--deny write` does
   not stop it although it runs arbitrary page code; a hermetic test pins that
   classification today. Documented in README; changing it is a policy call.
3. **Minor notes from the lanes**, recorded here for completeness:
   `_wait_url`'s prefix match (`got.startswith(want)`) can match a longer URL
   sharing a prefix; `_spec_matches` can list the same foreign tab twice in
   `skipped`; a failed `launch` leaves the browser running without saying so in
   the refusal; `launch-failed` cannot distinguish "no display" from "browser
   wedged" (child stderr is `DEVNULL`); `profile info` discards
   `unreadable` and can under-count; `audit.reset_redaction` is dead code;
   `ActionLog.write(args=...)` is typed `Any` (a bare string would iterate
   characters).
